| **GSAP ScrollTrigger** | 3.12.2 (CDN) | **核心组件**。用于将动画与滚动位置绑定，实现滚动驱动的视差、淡入、文本拆分等效果，是打造沉浸式浏览体验的关键。 |

#### 2. 动画实施质量评估

*   **实施专业度**：极高。从加载的 JS 文件（`GSAP Hero Text.txt`, `GSAP Text Global.txt`, `Videos Decoder.txt`）可以看出，开发者编写了**定制的 GSAP 时间线脚本**，而非使用简单的通用库。这表明对动画的控制粒度非常精细。

*   **动画过度**：**控制得当**。虽然使用了多个动画库，但核心是滚动触发，用户控制进度。没有检测到自动播放的、持续的、分散注意力的动画。动画是克制的，服务于内容。

#### 3. 动画性能评估

*   **GPU 加速**：GSAP 默认会使用 `transform` 和 `opacity` 进行动画，这两个属性是 GPU 加速的，不会触发 Layout 或 Paint，是性能最佳实践。**推测**：整个网站的动画应该主要基于这两个属性。

*   **滚动性能策略**：Lenis 和 ScrollTrigger 都使用了 `passive` 事件监听器（或等效策略），不会阻塞主线程。`requestAnimationFrame` 是 GSAP 和 Lenis 的默认行为，确保动画在每一帧的最佳时机更新。
*   **will-change 使用**：**推测**：GSAP 的 `defaults` 或特定动画中可能设置了 `will-change: transform, opacity`。但由于缺乏运行时数据，无法确认是否过度使用。专业做法是在动画开始前添加，结束后移除。

*   **确切技术栈**：**GSAP 3.12.2 + ScrollTrigger + Observer + Lenis 1.3.18 + SplitType**。

#### 可选的技术实施路线

*   **推荐保留**：**Webflow + 自定义代码**。对于当前阶段，这是ROI最高的方案。Webflow 负责内容管理和基础托管，自定义 GSAP 代码负责高级交互。团队应重点维护好自定义代码的文档。
*   **未来升级路线**：**Headless CMS (如 Contentful/Strapi) + Next.js/Nuxt.js + 自定义前端**。当业务复杂度超出 Webflow 能力范围时，可考虑此方案。这将提供最大的灵活性，前端可以完全重用并优化现有的 GSAP 动画体系，后端则拥有无限扩展能力。
